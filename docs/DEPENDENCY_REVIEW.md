2026-11-10 再次执行完整及生产依赖审计，仍分别为 6 项 moderate 和 0 项；公告及依赖链未变。公开 npm 元数据仍返回 electron-builder 26.18.0、minimatch 9.0.9/10.2.6，无当前父依赖范围内的修复回移。以下风险判断继续适用，本次没有修改依赖或锁文件。

## 实际告警与影响

`npm audit --json` 返回 6 项 moderate、0 项 high/critical；`npm audit --omit=dev --json` 返回 0 个已知漏洞。6 项是依赖及其传递影响，全部指向同一条 [GHSA-g3hv-75wg-m249 / CVE-2026-118764](https://github.com/advisories/GHSA-g3hv-75wg-m249)。11 月 3 日同一依赖锁曾返回 15 项，数量减少来自公告范围更新，不是本轮安装了修复。

本轮 npm 返回的公告范围为 minimatch `>=7.0.0 <11.0.1`。描述的触发条件是攻击者控制 glob 模式、预处理优化级别至少为 2，造成模式扩张和过量 CPU/内存消耗。不能据此宣称凭据泄漏或任意代码执行，也不能因为当前使用路径有限而将审计报告改为通过。当前 9.0.9 和 10.2.6 仍被标记，3.1.5 和 5.1.9 不在本次公告范围内。

## 为什么本轮不改版本

已通过公开 npm 元数据核对，electron-builder 最新版本仍为 26.18.0；minimatch 的 9、10 主版本最新分别为 9.0.9、10.2.6，仍落在公告范围内。修复从 11.0.1 开始，未找到当前受影响父依赖范围内的修复回移。

本轮 `npm audit` 建议将 electron-builder 降至 25.1.0，并标记 `isSemVerMajor: true`，不是当前构建基线的兼容补丁。也不能全局 override minimatch 到 11：旧版 ASAR、dir-compare 的实现使用可调用默认导出，且父依赖声明了不同主版本的范围；强行替换需要独立的 API 与构建兼容性验证。本轮未安装、升级、降级任何依赖，锁文件仅同步应用版本，未执行 `audit fix --force`。

## 现有约束与后续条件

- 构建模式来自仓库中受版本管理的配置，不从用户 Skill、市场结果或用户配置生成 glob；内置示例是仓库固定内容，真实本地库不参与打包。
- 当前 app-builder-lib 文件匹配入口使用 `{ dot: true }`，没有显式启用公告所述优化级别 2。此项是缩小当前暴露面的证据，不是对所有传递调用路径的无漏洞证明。
- CI 使用托管运行器、只读仓库权限，不注入签名或发布秘密，不自动上传产物。维护者仍应先审查不可信的构建配置及锁文件改动。
- 下一次候选发布前再次审计。上游提供兼容回移或 builder 支持修复后的依赖链时，再评估升级；若需要跨主版本，先验证资源筛选、ASAR 内容、Windows Setup/Portable、安装生命周期和保留的平台构建，再替换候选及重新生成 SHA-256。

结论：保留并公开记录构建期中等级告警；目前没有已确认、受父依赖支持的低风险修复路径。本轮不通过破坏性变更消除告警数字。
