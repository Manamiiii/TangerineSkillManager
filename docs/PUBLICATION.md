# 公开资料与隐私检查

公开源码、文档和演示使用通用路径：用户目录写作 `~` 或 `%USERPROFILE%`，应用数据写作 `{data}`，工程目录写作 `{workspace}`。测试中 `Example`、`Project` 是虚构路径，不需要创建这些目录。

## 本机信息存在哪里

应用在运行时读取当前操作系统的用户目录，不从源码取得作者的路径。Windows 的配置、来源和安装记录、备份及事件日志保存在 `%APPDATA%/skill-manager/`；macOS/Linux 使用各自的用户数据目录，详见 [配置说明](CONFIGURATION.md)。新用户从通用默认配置开始，项目列表与来源列表为空。

用户选择的工程路径、库位置和来源属于这台电脑的私有配置，不回写仓库中的示例配置，也不会由同步功能上传 GitHub。同步功能只写入用户指定的本地 Agent 目录。为核对文件操作，应用可以向本机用户显示真实路径；发布截图与反馈时仍需遮盖这些信息。

## 上传前

1. 不加入真实 `config.json`、`state.json`、备份、日志、凭据、便携程序、快捷方式或 `test-results`。这些本机文件已被忽略；即使强行加入暂存区，审计也会拒绝常见敏感文件类型。
2. 运行 `npm run audit:source`；暂存后再运行 `npm run audit:source -- --staged`。后一命令检查 Git 暂存内容，避免工作区已改好、旧敏感内容仍被提交的情况。
3. 逐张查看拟公开的截图。自动文本检查不能识别图片中的用户名、窗口标题、个人项目或 Skill 内容；不要直接上传设置页、原始错误截图和测试输出。当前 README 两张图使用虚构数据和路径模板。
4. 检查提交的作者/提交者邮箱，使用 GitHub 提供的隐私邮箱。不要把真实邮箱写入公开示例或构建脚本；公开 GitHub 仓库地址及第三方版权声明保留。

审计会检查当前账号、主机名、用户目录、工程位置、常见其他用户目录、凭据模式和私有服务地址，只报告类别，不回显命中的秘密。它是防误提交检查，不能保证发现所有秘密或图片内容；发现问题时先移出暂存区或替换为通用表达再提交。

## 源码公开与发行包

上传 main 不等于创建 Release。公开下载二进制前，按 [发布清单](RELEASE_CHECKLIST.md) 核对对应源码、许可证、签名说明与实际测试范围。自动构建产生的文件属于待验证产物，不等于全平台稳定发行版。
