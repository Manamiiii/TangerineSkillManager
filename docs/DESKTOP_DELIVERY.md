# 桌面验收交付

桌面启动入口是固定 Portable EXE 的快捷方式，不是源码服务。链路为 `.lnk → Portable 封装器 → 临时解包的主程序 → 包内 app.asar/UI`，不使用固定网页端口。更新源码或 dist 不会更新这个 EXE。日常点击不重新构建。

源码、Portable 与安装版共用本项目数据身份，其他工程使用各自身份。单实例锁保留旧路径约定以避免双写。**新 Portable 启动后可能把请求交给正在运行的旧版，然后正常退出；窗口出现、封装器退出码为 0 都不证明运行实例已更新。** 必须核对主进程实际版本和包来源，不能只读快捷方式文件名或页面上的版本文案。

## 每次维护的步骤

1. 阅读项目规则、检查 main/工作区、版本和预期提交。只检查本项目 .lnk 的目标、参数、工作目录、图标来源；若有脚本中转，继续读到最终执行文件。不要递归访问其他项目或安装候选“当前”目录。
2. 只读核对本项目进程、可安全获得的任务状态和数据布局。无业务状态接口时，进程存在即视为不能证明安全，不关闭或重启。检查布局仅取已知配置/迁移标记的存在性和文件类型，不扫描库或输出真实配置。
3. 复用与当前运行代码一致、散列和来源记录完整的候选；只改文档/维护测试时不重打包。运行代码发生变化则先在新的 `release/<验收批次>/` 构建，保留旧产物。不得覆盖在用文件，不隐式切到测试身份、空库或其他端口。
4. 执行必要源码检查和 `audit:package`，核对 ASAR 与构建输入、包版本及许可。对候选 Portable 执行现有隔离桌面验收。跨版本时增加下面的单实例转发检查，观察旧进程 PID 和实际版本仍未变化。
5. 若旧配置仍是普通文件且新迁移记录缺失，0.1.1 日常启动依赖 [显式迁移](DATA_LAYOUT.md)。没有真实迁移授权就保留原目标，并在快捷方式说明中标注旧版本和待切换原因。不要附加迁移参数、重定向环境或借双击完成迁移。独立验证通过只代表候选准备完成。
6. 在任务已结束、未保存工作已处理、数据兼容前置条件已完成且切换获授权后，备份本项目原 .lnk 到忽略的 `test-results/desktop-delivery/`。更新目标、工作目录和图标到已验证的同一批次；保留经核对仍适用的参数。回读所有字段和文件 SHA-256。只操作本项目启动入口，不操作安装器目录入口。
7. 实际启动仍须满足数据访问权限。允许正式启动时核对当前主进程版本、加载的包来源和数据身份；不能仅凭静态指向宣称新版实例已运行。正式启动不允许时明确写“入口已更新，真实启动未验证”。若阻塞，写“候选已验证，入口仍为旧版，待安全切换”。

## 隔离验证命令

```powershell
npm run build
npm run audit:package -- 'release/<验收批次>/win-unpacked/resources/app.asar'
npm run test:desktop -- --packaged '<候选 Portable 的绝对路径>' --portable
node scripts/portable-handoff-smoke.mjs 'release/<旧批次>/win-unpacked/Tangerine Skill Manager.exe' 'release/<新批次>/TangerineSkillManager-<版本>-win-x64-Portable.exe'
```

转发检查要求本仓库 release 中两个不同版本的真实产物。先用实际 Electron 预检隔离 home/AppData，再启动旧主程序和新 Portable，确认请求转发、旧 PID/版本不变、没有新库初始化或迁移。仅正常关闭本次创建的旧测试进程。旧包不可用时记录未验证，不能用改文件名或仅修改版本号冒充历史包。

本机 `test-results/desktop-delivery/` 保存入口回读、进程检查、候选来源/hash、阻塞和切换状态；可能包含私人路径，不提交或上传。公共说明使用路径模板。每次交接分别列源码提交/工作区、入口目标、产物版本/hash、真实实例状态、已完成和未完成验证。此流程不授权正式安装/卸载、真实迁移、发布或清理旧资产。
